# Project Delivery Suite

[![Bundle CI](https://github.com/ianyu1201/project-delivery-suite/actions/workflows/ci.yml/badge.svg)](https://github.com/ianyu1201/project-delivery-suite/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

Project Delivery Suite 是一套面向非专业开发者和 AI 协作团队的项目交付 Skill。它把项目启动、需求整理、开发会话、验证验收、版本治理和历史归档连接成一条连续流程，让用户只通过自然语言，也能把一个想法或混乱的旧项目推进为可开发、可验收、可继续迭代的完整版本。

当前版本：`0.7.0`。用户只需要使用一个 Skill：`$project-delivery-suite`。

## 解决什么问题

| 常见问题 | Project Delivery Suite 的处理方式 |
|---|---|
| 只有一个产品想法，不知道如何开始 | 梳理用户、问题、范围、风险和首版目标，形成项目启动方案与 PRD |
| 不懂 PRD、Git、测试和项目管理 | 用用户能理解的语言推进阶段，并生成开发和验收所需的文件与启动任务 |
| AI 对话越来越长，需求和代码开始漂移 | 把权威需求、冻结约束、项目状态和验证证据写入项目文件，让新会话从可信基线继续 |
| 一个项目存在 V1、V2、V3 等多个完整版本 | 识别当前批准版本、活动候选和历史版本，汇总 PRD、Issue、代码与测试，生成完整下一版 |
| 新版文档省略了旧版的重要要求 | 逐条验证已批准硬约束是否保留、迁移或被明确取代，发现静默遗漏时阻止交接和归档 |
| 新版本只是一组补丁，无法继续开发 | 创建包含完整代码、配置、测试、文档和未解决 Issue 的独立版本目录 |
| AI 声称已经完成，但没有可信证据 | 分开检查自动化测试、真实运行、独立验收和版本批准，给出最窄的真实状态 |
| 历史版本目录越来越混乱 | 新版本批准后，把全部前序版本统一整理到项目历史归档中 |

## 主要功能

- **新项目启动**：从一句想法开始，判断项目入口、规模、风险和首版最小闭环。
- **既有项目接管**：读取已有文档、代码、Git 和测试，建立可信的项目现状。
- **PRD 生成与治理**：优先复用项目现有 PRD；没有专业 PRD Skill 时使用内置规范生成可追溯、可审批的 PRD。
- **阶段化开发任务**：规划产品与设计、开发总控、独立验收等阶段，并在 Codex 中创建和登记新会话。
- **完整版本生成**：整合 PRD、Issue、代码、配置、迁移、锁文件、测试和必要资产，建立可独立继续开发的下一版本。
- **跨版本语义保真**：保护平台兼容、专有技术、导航结构、数据、安全、隐私、无障碍和验收等已批准硬约束。
- **Issue 延续**：已验证修复的问题退出活动清单，未解决或尚未验证的问题使用稳定 ID 延续到下一版。
- **验证与独立验收**：区分“代码已改”“测试通过”“真实运行通过”“独立验收通过”和“版本已批准”。
- **历史版本归档**：新版本批准后，将全部前序版本归入历史档案，并保持历史内容非权威、可追溯。
- **空间治理建议**：识别依赖、缓存和构建产物等可再生内容，但不自动删除用户文件。

## 一个 Skill，两个内部模块

Project Delivery Suite 内部自动路由两个模块，用户不需要分别安装或调用：

| 模块 | 负责内容 |
|---|---|
| 项目交付总控 | 项目启动、PRD、设计与工程合同、Codex 会话、开发推进、验证和独立验收 |
| 版本治理 | 多版本盘点、PRD/Issue/代码整合、语义保真、完整下一版和历史归档 |

当用户提出“基于 V3 开始下一版”时，版本治理模块先生成完整候选目录；候选安全物化后，项目交付总控模块再为新版本建立开发和验收会话。验证失败时继续修复当前候选，不会因为重试自动增加版本号。

## 特色

- **自然语言驱动**：不要求用户先掌握专业开发术语。
- **完整交付闭环**：同时覆盖项目开始、开发、验收、版本迭代和历史维护。
- **真正完整的新版本**：生成的是可以继续开发的完整项目目录，不是残缺补丁。
- **防止 AI 需求漂移**：目录收敛不等于治理完成，已批准硬约束必须逐条保真。
- **会话与项目状态联动**：自动区分“新会话”和“新版本”，并为新会话提供正确的工作目录、职责和冻结边界。
- **不依赖额外 PRD Skill**：安装专业 PRD Skill 可以增强效果，但缺失时不会阻断项目启动。
- **适应项目现有命名**：沿用用户已有的文件夹语言、大小写、前缀和版本规律，不强制套用固定名称。
- **敏感动作可控**：不会自动删除文件、上传项目、部署生产环境或清空废纸篓。

## 适合谁

- 有软件、App 或数字产品想法，但不熟悉完整开发流程的个人；
- 使用 Codex 和 AI 会话协作开发的产品负责人；
- 接手 AI 生成代码，需要重新梳理需求、代码和项目状态的人；
- 已经积累多个版本目录、历史 PRD 和 Issue 的项目；
- 希望建立可审计、可验收、可持续迭代流程的小型团队；
- 担心 AI 在改 UI、重写文档或整合版本时丢失硬约束的开发者。

## 使用示例

```text
使用 Project Delivery Suite，帮我从当前想法启动一个新项目。
```

```text
使用 Project Delivery Suite，接管当前项目，判断现在处于哪个阶段。
```

```text
使用 Project Delivery Suite，整合 V1、V2、V3 的 PRD、Issue 和代码，生成完整下一版。
```

```text
使用 Project Delivery Suite，为当前批准版本创建下一阶段的 Codex 会话。
```

## 安装

```bash
codex plugin marketplace add ianyu1201/project-delivery-suite
codex plugin add project-delivery-suite@project-delivery-suite
```

安装后新建一个 Codex 任务，然后直接说“使用 Project Delivery Suite”即可。
