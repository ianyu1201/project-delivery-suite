# 质量门禁、证据与独立验收

## 证据层级

从弱到强：叙述/旧摘要 → 静态代码检查 → 编译 → 单元测试 → 集成/UI 自动化 → 目标环境真实运行 → 独立复验。高层证据不能自动覆盖所有低层合同，但用户可观察结论至少要有运行证据。

安装包的 `scripts/self_check.py` 属于“静态检查、编译和合成夹具集成冒烟”的组合证据。它用于确认 WorkBuddy 实际安装载荷可运行，不等于交付仓库单元测试，也不等于真实项目、目标环境或独立验收。报告必须分别列出自检、单元测试、真实项目验证和宿主对话行为，不能因缺少 pytest 就把导入/`--help` 冒烟称为完整单元测试。

## 风险驱动验证

为每个工作包标记风险：产品逻辑、数据、导航、视觉、无障碍、性能、安全、迁移、硬件。按风险选择门禁，不机械要求所有项目运行同一套测试。

最低要求：

- 修改代码：相关测试和构建；
- 修改导航/数据/手势：自动化路径或可重复状态断言；
- 修改视觉/系统栏/动画：目标环境视觉抽样；
- 修改持久化/迁移：旧数据、失败和恢复场景；
- 控制实体设备：仿真/台架/安全停止/实机分层证据。

## 缺陷等级

- **P0**：数据不可恢复、严重安全/隐私、核心系统不可用或实体安全风险。
- **P1**：核心闭环无法完成、主要入口失效、稳定复现崩溃或关键结果错误。
- **P2**：重要但有绕行的体验、视觉、兼容或性能问题。
- **P3**：低影响瑕疵、优化建议或未来改进。

版本候选不得含未处置 P0/P1。P2/P3 是否允许由产品/发布责任人明确决定，不得静默遗留。

## 证据清单

截图前先建立覆盖矩阵：`coverage group → proof type → covered contract IDs → evidence equivalence key → capture checkpoint → planned artifact`。行为类要求不要为了方便而塞进截图组。

证据等价键至少包含：commit/build、页面/路由、UI 状态、数据夹具、设备/OS/viewport、方向、外观、语言、字号/无障碍设置、滚动/焦点/键盘/权限和时变状态。键完全一致的视觉要求共用一次截图；不同键可以在一次批量运行中连续采集，但仍是不同证据。

建立 manifest，每项包含：

- evidence ID；
- covered requirement/contract IDs；
- evidence equivalence key；
- commit 和构建；
- 环境/设备/OS；
- 初始数据；
- 操作步骤；
- 预期与实际；
- pass/fail/pending；
- 原始文件；
- 采集者和时间；
- 限制和未覆盖项。
- valid / invalidated 状态及失效原因。

在 `PROJECT_STATE.md` 结构化字段中记录开发交接、证据 manifest、独立验收报告、候选 manifest 和固定点的项目相对路径。聊天回复、任务状态或“用户已查看”不是文件证据。版本批准前 `validate_project_state.py --gate version-approval` 必须确认这些文件真实存在；内容真实性仍由独立验收负责。

截图和视频使用稳定命名，例如：`EVID-V03-UI-014-search-empty-iphone-se-max-text.png`。不要只保存“final2.png”。

最终候选 commit/build 改变时，最终验收视觉证据必须重建；开发中间提交可通过影响分析只废止页面、共享壳层、设计令牌、数据夹具或环境变化所影响的证据组。不得让一张旧截图静默覆盖新构建的多条任务。

## 独立验收

验收者接收：固定提交、合同、非回归矩阵、运行方式、证据索引和已知问题；不接收开发者对结果的主观结论作为事实。

验收顺序：

1. 确认提交、环境和工作区干净度；
2. 检查合同完整性与需求追踪；
3. 运行自动化门禁；
4. 复验关键用户路径和高风险场景；
5. 抽查开发证据真实性与对应关系；
6. 对视觉风险比较确认基线；
7. 输出逐项 `pass/fail/pending/not-applicable`；
8. 给出接受、条件接受或拒绝建议。

失败时创建限定范围的修复轮次；修复后重新固定提交并复验受影响合同和非回归范围。

独立验收通过只把 `acceptance_status` 设为 `accepted`。授权者随后给出单独版本批准，且 version-approval gate 通过，才允许设置 `version_approval_status=approved` 和 `current_approved`。

## 关闭用语

推荐：`本版本合同范围已完成；无已知 P0/P1；约定门禁与关键运行路径在所列环境通过；未验证项和允许遗留项见报告。`

禁止：`绝对没有 Bug`、`所有设备肯定正常`、`测试都过了所以 UI 没问题`。
