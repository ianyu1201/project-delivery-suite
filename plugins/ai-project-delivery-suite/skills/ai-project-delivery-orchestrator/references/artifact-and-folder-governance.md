# 交付物与文件夹治理

## 目录

1. 权威层级
2. 最小目录
3. 规模扩展
4. 素材与证据身份
5. 治理规则

## 1. 权威层级

建议从高到低：

1. 当前版本经确认的产品/设计与交付合同；
2. 当前固定 Git 提交中的代码、测试和配置；
3. 该提交对应的真实运行证据；
4. 工程决策和版本交接；
5. 历史版本、候选稿和旧对话总结。

代码回答“现在实现了什么”，不能单独回答“最终应该是什么”。运行证据回答特定环境中的观察结果，不能自动证明所有环境。

## 2. 最小目录

先适配项目现状。没有现役结构且用户接受编号式全生命周期目录时，参考 NOTE1 的稳定维度使用：

```text
project/
├── AGENTS.md
├── README.md
├── 00_项目治理/                 # 项目入口、状态、交接和目录索引
├── 01_产品/<version>/            # 唯一 PRD、产品范围和待决定项
├── 02_设计/<version>/            # 设计规格、候选和确认基线
├── 03_工程/                      # 现役代码、测试、规范和验收证据
├── 04_技术决策/                 # 已接受的长期 ADR
├── 05_独立实验/                 # 仅当真有隔离实验时创建
└── 90_历史归档/<version>/        # 历史、非现役材料或完整快照
```

编号表示生命周期和阅读顺序，不要为了补齐编号而预建空目录。源码和测试目录遵循技术栈惯例；不要为了模板改名活跃的 `ios/`、`src/`、`tests/`、`firmware/` 等目录。

完整版本快照项目仍保持每个版本自包含：当前完整版本位于现役区域，全部前序版本在新版本批准后移入 `90_历史归档/<version>/`。不得把发布文档子目录当成完整代码版本。

## 3. 规模扩展

小型项目可在对应编号目录的 `<version>/` 下直接放本版本权威产物。中型项目只在真有稳定责任时按范围、设计、合同、交付和验收继续分组。大型项目按独立工作包、安全、迁移、运维等真实责任增加目录。

不要预建空目录树。升级规模时保留稳定的编号入口或项目现有入口，通过索引迁移，不制造两个现役版本目录。

### 递进分层与低风险整理

整理既有目录时，先把散乱内容识别为总览、阶段交付物和历史归档，再决定是否移动。确有结构缺口时，先补总览与归档入口，再细分阶段目录。优先收纳散落文档和已结束任务材料，不轻易调整活跃代码树、外部工具引用路径或仍在使用的交付入口。

只有一个目录同时承载多个稳定维度、平铺已经明显增加查找成本时才继续分层。默认判断顺序是：

1. 阶段；
2. 用途；
3. 轮次、版本或模块；
4. 角色或交付物类型。

每增加一层都要同时满足：能减少查找成本、命名逻辑稳定、比原结构更容易交接和复盘。不要为了形式整齐建立空层级。

整理结果必须说明：整理前后的结构判断、保持不动的目录及理由、移动内容及理由、活跃与历史入口，以及后续新增文件的放置规则；拆到三级及以上时，还要说明每一层承载的分类维度。优先把这些信息写入现有 README、项目总览或目录索引；已有权威入口时不要重复生成平行的“目录结构说明”。

## 4. 素材与证据身份

严格区分：

- `media/reference/candidates/`：灵感、竞品、AI 候选图；不可作为验收基线。
- `media/reference/confirmed/`：用户明确确认的视觉基线，必须记录版本和适用页面/状态。
- `evidence/<version>/`：固定提交真实运行产生的截图、视频、日志和报告。
- 推广素材：若存在，单独存放；不能反向定义产品事实。

每项视觉文件登记：来源、身份、页面/状态、确认人/确认日期、适用版本、是否允许像素比对。文件名含 `candidate` 不等于完成登记；最终以索引为准。

## 5. 治理规则

- 同一事实只有一个权威解释，其他文件使用短指针。
- `AGENTS.md` 只放下次 Agent 不看到就会犯错的规则、命令和边界；不要复制 PRD。
- `README` 说明项目是什么、如何运行和从哪里继续；版本细节进入版本目录。
- 历史记录放 Git、归档或版本目录，不与现役文件并列冒充当前答案。
- 先机械盘点再决定归档；重命名/跨目录移动必须说明影响并获授权。本总控只组织历史，不移入 Trash、不永久删除；用户若需释放空间，自行删除已归档对象。
- 构建缓存、临时截图、编辑器状态、密钥和一次性调试文件不得进入正式交付。
- 每次版本冻结执行知识收尾：代码、运行态、文档、规则、记忆（如适用）和工作区分别标状态。
