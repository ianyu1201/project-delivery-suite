# 项目 Profile

只读取与当前项目相关的部分。Profile 调整技术门禁，不替代项目自己的规则。

## 通用软件

关注：用户闭环、模块边界、配置、依赖、数据、测试层级、部署/分发和回滚。目录遵循现有语言/框架惯例。

## 原生 iOS/macOS

增加：

- 最低 OS、目标设备、工程/workspace、scheme 和签名边界；
- SwiftUI/UIKit/AppKit 导航、状态所有权和生命周期；
- safe area、NavigationStack/TabView、键盘和系统 toolbar 所有权；
- 本地存储、迁移、后台/前台和附件；
- 默认/最大动态字体、VoiceOver、降低透明度/动态效果；
- Simulator 与真机证据的边界；
- 编译、XCTest/UI 测试、关键运行路径和视觉风险证据。

使用 Apple 平台专业 Skill；但仍要求页面实现与运行验收合同，禁止只在 Preview 验收。

## Web

增加：

- 支持浏览器、viewport、SSR/CSR、路由和刷新；
- API、认证、权限、缓存、错误/离线；
- 响应式布局、键盘、屏幕阅读器和对比度；
- 单元/组件/E2E、真实 URL 和构建产物一致性；
- 部署环境、变量、迁移和回滚。

## 机器人/嵌入式

增加独立合同：

- 机械、电气、固件、控制、感知、通信和上位机边界；
- 接口版本、单位、坐标系、频率、时延和故障模式；
- 模拟器、台架、受控实机和现场分层测试；
- 急停、限位、超时、失联、安全状态和人工接管；
- 硬件版本、固件版本、校准、测试治具和环境；
- 实体风险评估、回滚/降级和不可逆动作授权。

安全关键项自动视为大型/高风险。不得让并行 Agent 未经集成审查同时更改共享硬件接口。
只要机器人包含 Web/App/屏幕控制界面，同时应用 UI 实现与运行验收合同；硬件安全合同不能替代界面布局、状态、手势、导航和真实设备验收。

## 软硬件混合

除各 profile 外，建立端到端兼容矩阵：App/Web、云/本地服务、固件、硬件修订和协议版本。每个版本明确兼容组合、升级顺序、失败恢复和现场验证证据。
